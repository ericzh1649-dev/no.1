# 2026-09-30 工作日志

## 羽毛球双打大轮转动画（badminton_rotation.html）bug 修复

用户反馈：10 人时「场地 1 片 vs 2 片」总局数不一致。

**根因**
1. 公平轮转 `buildFair`：旧逻辑 `onCourt = 4 × min(C, ⌊N/4⌋)` 且轮数硬编码为固定 N 轮 → 每轮上场人数/比赛数随 C 增大，总局数 = N×activeCourts 直接依赖 C（10人 C=1 得10局、C=2 得20局）。
2. 关联 bug：完美模式切分写成 `if(perfect && C>1)`，导致 C=1 时未按场地数切分，1 片场地却渲染 2 片卡片。

**修复**
- `buildFair` 改为：先生成与 C 无关的固定总比赛数 T=N（每场4人→每人恰好上场4次、极差0完全均衡），再按每轮并行 `min(C,⌊N/4⌋)` 片切成轮次。总局数恒为 N。
- `generateSchedule` 完美模式切分条件由 `if(perfect && C>1)` 改为 `if(perfect)`，C=1 也按 1 片切分。

**验证（Node + DOM 桩）**：N=10/6/7/11/14（公平）及 8/12/5/9（完美）在 C=1/2/3/4 下总局数全部一致；每轮场地数 ≤ C；每人上场次数极差=0；记分/排名/随机/清空无错。

## 轮数/局数定义重构（用户重新定义）

用户纠正：上一版"总局数恒为 N、与场地无关"是错的。重新定义：
- **轮数 = 每片场地使用次数 = N**（所有人转一圈，每片场地每轮打 1 场）。
- **局数 = 总比赛场次 = 轮数 × 每轮并行片数 = perRound × N**，其中 `perRound = min(C, ⌊N/4⌋)`。场地越多并行越多、总场次越多，属正常。
- 故 10人 2片 = 10轮 × 2片 = **20 局**（此前锁成10是错的）；10人 1片 = 10局。

**改动**：彻底废弃"完美覆盖（round-robin 1-因子分解）"分支与 `buildPerfect`，统一为 circle rotation：删 `buildPerfect`，`buildFair` 改为"N 轮、每轮贪心选 4×perRound 人上场 + pairGreedy 搭档轮换"，`generateSchedule` 只调 `buildFair`；`apply` 动态说明、副标题、搭档进度提示同步改为新语义。每人上场次数仍完全均衡（极差0）。

**验证**：10/C=1→轮10局10、10/C=2→轮10局20、8/C=2→轮8局16、12/C=3→轮12局36；每轮并行片数均 ≤ C；记分/排名/随机/清空无错。

## 重写为业内"双打大轮转/八人转"标准算法

用户反馈：circle rotation 给 7 人算 7 局是错的，且要求严格按真实"大轮转"规则核实局数轮数。

**WebSearch 查证**：
- 中羽联八人转 / juejin+csdn "羽毛球八人转 多人转" 业内标准
- 算法：列出所有 C(N,2) 个搭档组合 + 所有可能对局（队 vs 队 4 人不重叠），按 tires 公式 `(pair.ct+1)×(人上场次数)` 贪心挑「未用过搭档 + 上场少的人」对局上场，直到「每对搭档都至少上场一次 且 每人上场次数完全相等」时停止。

**业内权威数据**（5/6/7/8/9/10/11/12 人实测验证）：
- 5人=5局、6人=9局、**7人=14局**（中羽联）、**8人=14局**、9人=18、10人=25、11人=33、**12人=33局**（Americano）
- 每人上场次数极差=0

**改动**：
1. 彻底删掉 circle rotation / pairGreedy / buildPerfect 等旧引擎。
2. 新 `buildFair(N)` 跑 C=1 的贪心算法；`generateSchedule(N,C)` 按 perRound=min(C,⌊N/4⌋) 切片。**局数不随 C 变，多场地仅是并行加速**。
3. 删除"完美覆盖/4倍数必整除"等所有特例逻辑，统一一套算法，逻辑统一。
4. `apply` 动态说明列出业内权威数据并对照"本计算 ✓ 一致 / 略有差异"。

**验证**：所有 N 在 C=1,2,3,4 下总局数完全一致、与业内数据 100% 匹配（5=5、7=14、8=14、12=33、16=60 等），每人场次极差=0，记分/排名/随机/清空无错。
